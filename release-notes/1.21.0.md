## 1.21.0 — Flight Lifecycle, Taxi, Traffic, Media & Navigation

### Flight Tracking & automatic recording
- Planned Take-off and Landing times are shown next to the actual event times. SimBrief planned OFF/ON times are preferred when available; missing planned values remain `–`.
- Automatic flight completion now requires a stable post-landing parked state instead of a single signal: on ground, very low speed, engines off and parking/gate context for a sustained period. Without a recognized gate, a longer stable stop is accepted.
- Temporary SayIntentions/SimConnect identity changes no longer split a flight when origin and destination still describe the same active flight.
- Departure and Arrival taxi routes are retained separately and stored with the active flight record.
- Planned taxi routes are shown on Flight Tracking as red dashed overlays, clearly separated from planned airborne route and the amber actually flown track.
- Live simulator traffic is shown on the Tracking map as heading-oriented aircraft symbols with callsign tooltip and detailed popup.
- The separate Live Traffic/Flightboard navigation entry is removed; traffic is consolidated into Flight Tracking.
- A manual **FLUG BEENDEN** action remains available as a confirmed fallback.

### Taxi tool
- Taxi clearances from SayIntentions are now classified strictly. Take-off/landing clearances, frequency changes, heading/altitude instructions, general traffic messages and unrelated messages no longer replace the active taxi route.
- Taxi deviation guidance uses a wider practical corridor, a longer persistence threshold and suppresses off-route warnings during very-low-speed maneuvering/pushback-like states.
- Arrival taxi planning can be prepared while still airborne. A **ZIELFLUGHAFEN ÜBERNEHMEN** action transfers the active flight destination to the airport search without letting aircraft position override the selected planning airport.
- Arrival planning exposes runway-exit choices derived from taxiways intersecting/approaching the selected runway. `Exit noch unbekannt` remains available; when an exit is chosen the route starts at that exit.
- The selected ICAO remains the authoritative planning focus. Taxi map max bounds are constrained to the airport area so streets/cities outside the airport cannot become the working context.
- Ownship is filtered from ground-traffic conflict detection using stable identities and a position/altitude/speed plausibility fallback.

### Screenshots & recordings
- Adds a dedicated **Medien** app.
- Screenshots can be captured and are physically persisted against the active flight with timestamp/callsign filenames.
- Screen recordings use the operating-system/browser capture chooser, show a persistent recording indicator and elapsed time, and upload progressive chunks so partial data is recoverable if a session ends unexpectedly.
- Recordings and screenshots remain available after restart, can be previewed, opened and deleted, and are associated with the active flight or `unassigned` when no flight is active.

### Home, Apps & navigation
- Removes the non-actionable Home status texts requested in the backlog.
- Home tiles show one clear application name; explanatory subtitles/categories are visually removed.
- Large redundant page-heading chrome is suppressed where the app toolbar already provides context.
- The global app button is presented as a consistent **HOME** button with a house icon.
- Traffic duplication is removed from Home/navigation and redirected to Flight Tracking.
- A new aviation-style Media icon is included without emoji assets.

### Stability
- Active flight, taxi route, media and tracking context share the same flight record and survive app navigation.
- Existing release validations remain active and 1.21.0 adds dedicated regression checks for lifecycle, taxi classification, runway-exit planning, ownship filtering, media persistence and release wiring.

> Flight simulation use only — not for real-world navigation.
