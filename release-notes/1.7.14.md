## 1.7.14 — COM Usability & Layout

- Reworked the **COM page layout** for clearer spacing, stronger hierarchy and better use of the available desktop width while retaining responsive tablet/mobile behavior.
- Cleaned up the **COM1 / COM2 radio cards**, frequency displays, action buttons, RX/TX state chips and the next-station recommendation card in both dark and light themes.
- Frequency suggestions in **Available Frequencies** are now genuinely interactive: clicking the frequency area explicitly sends the selected frequency to **COM1 Standby** when MSFS is connected.
- The existing **COM1 STBY / COM2 STBY** buttons remain available for precise radio selection; keyboard activation with Enter/Space is supported for the suggestion itself.
- When MSFS is offline, a frequency suggestion is no longer a dead control: clicking it stages the value in the COM input and clearly explains that simulator connection is required before tuning.
- Pressing **Enter** in a COM frequency input now performs the guarded Standby action when possible, with validation for the VHF COM range **118.000–136.990 MHz**.
- Invalid frequencies receive an immediate visible validation state; staged frequencies and action feedback are shown clearly.
- Empty/offline radio values such as `0.000` are presented as **—** instead of looking like a valid tuned frequency.
- Available-frequency rows now highlight frequencies that are already **Active** or **Standby** on COM1/COM2.
- Added dedicated **COM UI regression checks** covering required DOM contracts, frequency parsing/validation, explicit-click behavior, keyboard interaction, light theme and responsive rules.
- Release preparation now explicitly injects and cache-busts the COM polish CSS/JS and includes both files in the service-worker application shell.
