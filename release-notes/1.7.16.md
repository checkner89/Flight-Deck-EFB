## 1.7.16 — Ground Services & GSX Remote

- Reworked the **Ground Services** page into a wider, balanced 12-column dashboard so GSX status, turnaround, live services, safety and payload data use the available screen space instead of leaving large empty areas.
- Added dedicated **OVERVIEW** and **GSX REMOTE** tabs to separate Flight Deck's read-only/guarded GSX telemetry from the official interactive GSX browser interface.
- Added an embedded **GSX Pro Web Remote** workspace for GSX Pro 4.0.6+ using the official Couatl Remote Control Server instead of recreating or reverse-engineering GSX service controls.
- The GSX Remote address defaults automatically to the same Windows host running Flight Deck on port **8744**, which also works when Flight Deck is opened from a tablet or second PC on the local network.
- Added an editable remote address field for installations that use a different GSX Remote port, with **LOAD REMOTE**, **RELOAD** and **OPEN SEPARATELY** actions.
- Added guidance for the GSX **Settings → Network** page introduced with GSX 4.0.7, where the Remote Control Server address and port can be confirmed.
- Kept the existing Flight Deck GSX integration intentionally safe: documented GSX LVars continue to provide service/payload status while interactive service commands remain inside the official GSX Web Remote.
- Improved the live-service area to span the page width and rebalanced **Ground Safety** and **Payload Sync** into equal-width cards beneath it.
- Added dedicated responsive layouts for desktop, medium windows, tablets and phones, plus explicit light-theme styling for the embedded-remote connection controls.
- Added permanent **Ground Services / GSX Remote regression checks** covering URL normalization, default port behavior, required Ground DOM contracts, tab/iframe creation, responsive rules and release asset injection.
- Changelog and release-note entries continue to use **bullet points** consistently.
